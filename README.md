# 🧮 経理人生ゲーム ～3月決算の一年～

経理業務を人生ゲーム形式で楽しめる、1人用のブラウザゲームです。
3月決算の上場会社の経理部員になって、4月（期首）から3月（期末）までの経理イベントをサイコロで駆け抜け、CFOを目指します。

ビルド不要の静的サイト（HTML / CSS / JavaScript ES Modules）なので、そのまま GitHub Pages で公開できます。

## 遊び方

1. 名前・入社のしかた・プレイする期数（1期／3期／5期）を選んでスタート
2. サイコロを振って、4月の START から3月の決算日 GOAL まで蛇行する道を進む
3. 分かれ道では進むルートを選び、止まったマスのイベントに対応する

| 要素 | 内容 |
| --- | --- |
| 💴 給料日 | 月をまたぐと「月給 − 生活費」が所持金に入る（3月分は決算日に支給） |
| 📚 スキル | 判定のボーナス（スキル20ごとに +1）。クイズや業務で上がる |
| 🤝 信頼 | 賞与の支給月数（1.5〜2.5か月）と昇進に影響 |
| 😵 ストレス | 100になると体調を崩して1回休み |
| 🏁 決算日（3/31） | 必ず止まるマス。「スキル＋信頼」の評価ptで昇進判定 |
| 🎓 簿記検定 | 11月は必ず通る。6月・2月は分かれ道しだい（1級は6月・11月のみ）。課長以上は2級、CFOは1級が必要 |
| 🔀 分かれ道 | 1期に3か所。選んだルートは結果画面の「各期の決算」に記録される |
| ⏩⏪ 進む・戻る | 「2マス進む」「失敗で3マス戻る」など。戻るときは通ってきた道を引き返し、分かれ道より前まで戻ればルートを選び直せる。移動先のイベントは起きない（決算日だけは例外）。同じ月の給料は1期に1回だけ |

業務マスでは「🎲＋スキル補正 ≧ 目標値」で成否を判定します。残業すれば判定＋2、ただしストレスが増えます（管理職になると残業代は出ません）。
最終期の決算日を迎えると「人生の決算報告」として、資産・役職・資格・スキル・信頼・家族などから合計点と称号が決まります。

### 盤面の道のり（3月決算）

| 時期 | 道 | 主なマス |
| --- | --- | --- |
| 4〜5月 | 共通 | 新年度スタート、期末監査、決算短信、法人税等の確定申告（5/31） |
| 6〜7月 | 🔀 📘 開示ルート | 有価証券報告書（6/30）、定時株主総会、IR説明会（ハードだが伸びる） |
| | 🔀 🧾 税務・労務ルート | 簿記検定（6月）、労働保険の年度更新、算定基礎届、チャンス |
| 7〜9月 | 共通 | 第1四半期決算、夏の賞与、夏休み、予算実績管理、⏩連休前の前倒し、中間決算（9/30） |
| 10月 | 🔀 🚀 プロジェクトルート | 新会計システム導入、M&Aのデューデリ、⏪本番稼働（失敗で3マス戻る） |
| | 🔀 🗃️ 定常業務ルート | 決算整理仕訳、期中レビュー、ライフイベント、有給休暇 |
| 10〜2月 | 共通 | ⏪税務調査、半期報告書、簿記検定（11月）、中間申告（11/30）、年末調整、法定調書（1/31）、第3四半期決算短信 |
| 2月 | 🔀 🧭 経営企画ルート | 次年度予算策定、取締役会で報告、中期経営計画 |
| | 🔀 📚 資格・学習ルート | 仕訳クイズ、簿記検定（2月）、会計セミナー、ライフイベント |
| 3月 | 共通 | 実地棚卸、決算準備、⏪年度末の駆け込み精算、決算日（3/31） |

1期で通るのは約45マスです。決算日の次はまた4月の START に戻り、次の期も分かれ道を選び直せます。

ほかに、仕訳クイズ（32問）・チャンス（⏩2マス進むもあり）・ハプニング（⏪1〜3マス戻るもあり）・ライフイベント（結婚、出産、マイホーム など）があります。
進行状況はブラウザの localStorage に自動保存され、「つづきから」で再開できます。

## ローカルで動かす

ES Modules を使っているため、`file://` ではなくローカルサーバー経由で開いてください。

```sh
npm start          # = python3 -m http.server 8000
# → http://localhost:8000 を開く
```

## テスト

依存パッケージはありません（Node.js 22 以上）。

```sh
npm test           # ゲームロジックのユニットテスト（node:test）
npm run simulate   # ランダム自動プレイでバランス（役職・称号の分布）を確認
```

## GitHub Pages へのデプロイ

`.github/workflows/deploy.yml` で、`main` ブランチへの push 時にテスト → デプロイが実行されます。

1. このリポジトリを GitHub に push する
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
3. `main` に push すると `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

（Actions を使わない場合は、Source を「Deploy from a branch」→ `main` / `/(root)` にしても動きます）

## ファイル構成

```
index.html          画面（タイトル／ゲーム／結果）
css/style.css       スタイル
js/constants.js     役職・資格・入社のしかたなどの定数
js/rules.js         給与・賞与・判定補正などの計算
js/quizzes.js       仕訳・経理知識クイズ
js/events.js        盤面（道・分かれ道・マスの配置）とイベント定義
js/engine.js        ゲーム進行ロジック（DOM非依存）
js/main.js          画面制御
tests/              ユニットテスト
scripts/simulate.js バランス調整用シミュレーター
```

※ ゲーム内の期限・制度は一般的な3月決算の上場会社を想定した簡略化です。実務では最新の法令・社内規程をご確認ください。
